# Implementation Plan

## Locked corrections, gates, and implementation decisions

- **Gate A — local deadline MVP (blocking, network-independent):** bundled-PDF ingestion, deterministic calibrated BM25, extractive-only cited answers, abstention/safety, FastAPI health/chat, secret-free configuration, and backend tests. The accepted MVP never sends a medical answer to a generative provider.
- **Gate B — complete rebuild (blocking after Gate A, independent of Gate C):** the three exact Kaggle versions, merged deterministic corpus/SFT artifacts, dense/hybrid/reranked retrieval and calibration, safely gated provider plumbing and Kiro connectivity evidence, repaired Swift client, CI/security, and deterministic Lightning transfer bundle. External acquisition or macOS limitations must produce a distinct `BLOCKED_EXTERNAL_*`/`PENDING_MACOS_VALIDATION` component status rather than a success claim.
- **Gate C — optional external-GPU enhancement (non-blocking):** QLoRA/PEFT execution starts and remains `PENDING_EXTERNAL_GPU` unless the user elects it and a real A100 run emits the required hashed artifacts. Gate A and Gate B can pass without an adapter; no training, tuned-model consumption, or quality gain may be claimed from scripts, dry-runs, or plans.
- **Original acceptance-criterion ownership:** Gate A owns criteria 1, 2, 4, and 6. Gate B owns criteria 3, 5, 7–13, 17, and 18; criterion 18 is narrowed to reproducible bundle/bootstrap creation and clean-extraction validation. Gate C owns criteria 14–16 and 19, plus the real paid-run portion formerly embedded in criterion 18. This assignment supersedes any wording that made QLoRA mandatory.
- **Grounding decision:** `generation_mode=extractive` is the only accepted default. Optional Kiro/Ollama/PEFT-generated candidates stay unready until claim-support calibration passes for `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli` at revision `6f5cf0a2b59cabb106aca4c287eed12e357e90eb`; citation syntax alone is never evidence, and one unsupported claim rejects the whole candidate before extractive/abstention fallback.
- **Lexical-support decision:** raw BM25 is retained for ranking and never normalized by the query winner. Support requires positive query IDF mass, calibrated positive-IDF lexical coverage, calibrated raw-score floor, and at least two distinct informative term matches (one only when the query has exactly one informative term); readiness remains false until answerable and adversarial-unanswerable calibration yields zero false support.
- **Acquisition decision:** pin `kaggle==2.2.4` and pass `owner/slug/version` to its official version-aware calls, which populate `dataset_version_number`; compare versioned metadata before and after download and permit strict fallback only from the configured SHA-256-valid archive cache. Never fetch or bundle `rcratos/ayurveda-texts-english/1`.
