# Offline-first extractive RAG rebuild with iOS and optional QLoRA handoff

This change replaces the broken prototype with a Python 3.11 FastAPI/RAG backend, deterministic data preparation, an in-repository SwiftUI client, and optional provider and external-GPU workflows. Gate A is intentionally extractive-only; Gate B truthfully remains blocked on Kaggle data, Kiro remains unverified, macOS validation remains pending, and Gate C remains `PENDING_EXTERNAL_GPU`. The branch is clean and committed, but several safety gates and completion checks do not enforce the locked behavior.

Watch for: **confirmed** hybrid retrieval can declare support without the required raw-BM25 evidence; **confirmed** full calibration can remain ready after its evaluation set changes; **confirmed** the external adapter workflow can mark Gate C complete without testing generated adversarial answers or requiring safe evaluation results; **confirmed** the required mypy check currently fails.

## Hybrid support bypasses the locked raw-BM25 gate

**Confirmed.** `retrieve()` marks hybrid candidates supported when either `lexical_support` or `dense_support` passes, then full mode only adds a reranker threshold. A candidate with zero positive query-IDF mass, zero informative overlap, or a BM25 score below the calibrated floor can become a supported medical context solely from embedding similarity. This contradicts the locked rule that support requires positive query IDF, calibrated lexical coverage, calibrated raw score, and the required distinct informative matches in every retrieval mode.

The full and hybrid calibration loops optimize dense/reranker thresholds against the same predicate. Dense and reranker signals may rank or further restrict candidates, but must not replace lexical support. Add regression cases where a dense-near candidate fails each lexical requirement and remains unsupported in both `mvp_hybrid` and `full`.

## Retrieval calibration is incomplete and not durably evaluation-bound

**Confirmed.** `eval/golden.jsonl` has one synthetic answerable row and only random, entity-swap, and irrelevant unanswerables; required typo and negation adversaries are absent. Gate A's default calibration instead derives answerables from document questions and uses four hard-coded unrelated queries, again without typo or negation cases. The reported zero false support applies only to this reduced set.

**Confirmed.** Full-mode calibration incorporates the supplied golden file into `evaluation_hash`, but `load_calibration()` validates that hash only for `bm25_only`. A full calibration created with `--golden eval/golden.jsonl` remains ready if that file changes. Persist the evaluation source/hash for every mode, validate it on load, and add stale-golden tests for BM25, hybrid, and full retrieval.

## API history is accepted outside the public contract

**Confirmed.** `ChatRequest` limits history length but does not require alternating complete `user`/`assistant` pairs. `render_grounded_prompt()` silently recovers any valid-looking pairs from malformed input instead of returning the locked normalized 422. Require even length and exact pair ordering at the model boundary, with API tests for odd, assistant-first, duplicate-role, and broken-middle histories.

## Gate C can complete without a real adversarial safety evaluation

**Confirmed.** `training/evaluate_adapter.py` generates model answers only for held-out rows. Its `adversarial_count` is the length of static strings passed through the rule-based query classifier; those prompts are never sent to the adapter. The report may contain a positive `unsafe_candidate_count`, while `finalize()` checks only nonzero counts and two booleans from one RAG smoke, so an unsafe and adversarially untested adapter can become `COMPLETED`.

Generate and assess adapter answers for the required adversarial, diagnostic, dose, citation-laundering, and safety prompts. Finalization must verify per-case records and hashes, enforce the safety thresholds, and require the RAG smoke to demonstrate support-verified generation or safe fallback rather than provider invocation alone.

## Final gate derivation trusts status files instead of required artifacts

**Confirmed.** `final_gates.derive()` copies Gate A's status without checking current input hashes or required booleans. It also retains any Gate C report whose status is `COMPLETED` without verifying the checkpoint, adapter, evaluation, serving files, or their hashes. Stale or edited JSON can therefore become the final summary after its evidence disappears.

Derivation should independently validate Gate A and call a side-effect-free Gate C evidence validator. Inject forged and stale PASSED/COMPLETED reports in tests and require the summary to fail closed.

## Required type-check verification is red

**Confirmed.** `scripts/verify_all.sh` stops at strict mypy with six errors: three `no-any-return` errors in `src/acharya/lightning.py`, unused ignores in `src/acharya/ingest/download.py` and `src/acharya/preparation.py`, and a redundant cast in `src/acharya/preparation.py`. The checked-in CI workflow fails at the same stage. Correct the annotations and ignores, then rerun the complete orchestrator.

## Dataset cache replacement has a destructive activation window

**Confirmed.** `acquire_dataset()` deletes the existing version directory before replacing it with verified staging, and `_activate_cached()` does the same for the extracted directory. A filesystem failure between deletion and `os.replace()` removes the last valid cache, violating atomic activation and failure-preserves-active behavior.

Use an atomic pointer or rename/rollback sequence that preserves the current valid target until replacement commits. Add injected replacement-failure tests for downloaded and cached activation.

## Handoff archive validation has no resource limits

**Confirmed.** `bundle.validate_archive()` rejects traversal, links, and special members, but streams arbitrary member counts and sizes to disk without compressed-size, expanded-size, per-member, or member-count limits. `final_gates` invokes it for every matching handoff archive, allowing a corrupted transfer to exhaust disk before integrity validation. Enforce explicit limits before and during extraction and test oversized and high-expansion archives.

## MedQuAD licensing is internally contradictory

**Confirmed.** `configs/datasets.yaml` records MedQuAD as `Apache 2.0`, while README calls it `CC0-1.0 as recorded in configs/datasets.yaml`. Preparation and bundle attribution use the config value, so operator documentation and emitted attribution can disagree about redistribution obligations. Verify the exact selected version's license, make both sources identical, and regenerate attribution after real acquisition.
